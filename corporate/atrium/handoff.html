The system, and how it was decided.

Every specimen below is the live token or the live component — this page is built out of the same system it documents, so it cannot describe something the site does not do.

Brand

The mark, and the one colour it owns.

Three tapered bars over a letterspaced wordmark, rebuilt as inline SVG from the company’s own logo so it stays sharp at every size and inherits colour from its context.

Wiseman Residential
  • One colour, reserved. #1C6775 belongs to the mark and to nothing else on the site. Body text, buttons and links never use it.
  • It inherits. The SVG is fill="currentColor", so the mark is teal on cream, cream on the deep ground, and never needs a second file.
  • Clear space. One bar-width on every side. Minimum height 18px, below which the taper stops reading.
  • Never the placeholder. The generic three-rectangle mark used in early drafts is retired; the bars are tapered, and the taper is the mark.

Colour

Twelve tokens, and the contrast each one clears.

Nothing is a raw hex in a component — every colour is a named custom property, so a change lands in one place. Each text colour was measured against both grounds it can sit on.

  • --bgGroundThe warm cream every page stands on.#F3F0E7
  • --bg-2Tinted bandOne step down, for alternating sections.#EFEADD
  • --raisedRaisedThe frosted header and lifted surfaces.#F7F4EC
  • --inkInkHeadings, primary buttons. 8.8:1 on cream.#144952
  • --ink-2BodyEvery paragraph. 7:1 on cream.#42585B
  • --ink-3MetaCaptions, citations, spec keys. 4.80:1 — AA.#5D6C6F
  • --deep-tealDeepPage-transition ground and dark sections.#092D34
  • --accentTerracottaDecorative keylines, ticks, marks.#C8784D
  • --accent-inkTerracotta inkLinks and chips. 4.95:1 cream, 4.70:1 stone.#9A5533
  • --brand-tealThe markThe client's own logo colour. Reserved for the mark.#1C6775
  • --tideTideLight teal, only on dark grounds.#A8C9CE
  • --sandSandRare warm highlight.#FEDA77

Ratios measured against --bg cream. AA requires 4.5:1 for body text and 3:1 for large text; every text token above clears it on both the cream and the tinted ground.

Montserrat · interface and figures

FIND A HOME  ·  $4,895–$5,095  ·  72 BUILDINGS

Buttons, labels, eyebrows and every number. Figures are tabular so columns of rent and bedroom counts line up rather than shimmer.

  • No orphans. Headings never end with a single word on its own line — non-breaking spaces are written into the copy, not left to chance.
  • One scale. Every size is a clamp() between a phone and a desktop value, so nothing steps at a breakpoint.
  • Measure. Body copy is capped near 62 characters; captions near 70.

Information architecture

Corporate first, renters one click away.

The structure follows the model the client pointed at — a company that leads with who it is — while keeping the person looking for an apartment on a direct path. Five sections, plus a standing Find a home button.

Top level

  • About WisemanWho the company is. The culture and corporate layer.
  • Live at WisemanEvery renter path: search, buildings, areas.
  • Work at WisemanOn-site management, maintenance, leasing, office.
  • Track RecordWhat is built and what is filed, each figure cited.
  • ContactSix ways in, routed by what the visitor needs.

The Find a home button sits outside the five, in teal, on every page — so the commercial path never competes with the corporate narrative for a nav slot.

Page families

  • Editorial pages 9

    Company, careers, track record, residents, contact and the legal set. One template, image-led.

  • Building pages 72

    One per building: floor plans, amenities, its own office and phone, its own map.

  • Area pages 7

    One per Los Angeles area, with the buildings in it and what is nearby.

  • Index pages 4

    Home, the property search, every building, the seven areas.

Four templates carry 95 pages. A new building is a row of data, not a new page design.

  • Every building is a real page. 72 of them, each linkable, each with its own office, phone, plans and map — not a modal over a list.
  • Areas are a layer, not a filter. 7 area pages give Los Angeles neighbourhoods their own addressable content; 52 named streets appear across the portfolio.
  • The leasing system is named, not hidden. Resident and applicant logins are marked as a separate system rather than mixed in with the site’s own pages.

Components

Ten shared modules, four surfaces.

The corporate site and every property site draw on the same files. A fix to the map, the search or a rail lands everywhere at once — which is what makes 72 building pages affordable to maintain.

  • base.cssReset, tokens, header, footer, buttons, page transition.
  • core.jsData loading, header behaviour, reveals, reduced-motion flag.
  • search.cssFilter bar, dropdowns, chips, the results column.
  • search.jsFiltering, sorting, URL state, the more-filters dialog.
  • map.cssLeaflet skin, price pills, dot pins, area bubbles.
  • map.jsTiles, pins, pill thinning, map-to-row highlighting.
  • rail.cssHorizontal rails: hidden scrollbar, arrows, focus ring.
  • rail.jsArrow and keyboard control for every rail on the site.
  • editorial.cssLong-form pages: heroes, row tables, forms, legal set.
  • icons.svgOne sprite: amenities, building features, social, EHO.
  • One button system. Solid deep teal, cream text, letterspaced caps, square corners. A secondary is the same button with a hairline instead of a fill. There is no third.
  • No visible horizontal scrollbars. Rails are driven by arrows and the keyboard; the scrollbar is hidden by design, and the track is focusable so it is still reachable without a mouse.
  • Map pins are dots. Plain dots everywhere, flat price pills on search maps only — no numbers on pins, which read as a count of homes, and no tails.

Motion and content

One curve, and a rule about every sentence.

Motion

A single easing curve across the estate, cubic-bezier(.16, 1, .3, 1). Pages leave under a cover and arrive with a reveal rather than sliding. Everything is cancelled under prefers-reduced-motion.

Figures

Counts, rents and bedroom ranges are computed from the live leasing feed at build time. No page hand-writes a number, so nothing can go stale independently of the data.

Claims

Anything only the company can confirm shows a [CLIENT] marker instead of a plausible guess. The site ships honest and fills in as answers arrive.

  • Fair housing is a writing rule. Copy describes the apartment, never the household. Neighbourhood text stays on transit, distance, parks and named streets. The Equal Housing mark appears in every footer at no less than the size of the Wiseman mark.
  • Accessibility is built in. WCAG 2.1 AA: contrast measured on both grounds, visible focus on every interactive element including scroll containers, keyboard paths through the filters, the map and every rail, semantic lists and sequential headings. No third-party overlay — they measurably increase litigation risk for housing sites.
  • Copy is short on purpose. Roughly 450 words on the home page. Where a sentence is doing no work, it is cut rather than softened.

Roadmap

Five phases to launch.

Durations are working estimates for one designer-developer. Phases 1 and 2 run in parallel; only the items marked as Wiseman’s can stall the schedule.

  1. Phase 0 · ~1 week

    Settle the record

    Entirely on Wiseman, and nothing else can be written until it is done. We hand over the fact-check dossier and the claims sheet every page will be built against.

    Wiseman provides a founding year in writing · a decision on “over 45 years” and “100+ communities” · the responsible broker entity and DRE number · leadership names and bios · a values statement.

  2. Phase 1 · ~3–4 weeks

    The corporate site

    All 95 pages to production, the legal set to counsel-review draft, a full accessibility pass, a redirect map from every existing URL, analytics and search console.

    Wiseman provides vector logo files · which Instagram handle is canonical · counsel review of the legal drafts · corrected address of record on CSLB, BBB and Archinect.

  3. Phase 2 · ~2 weeks, parallel

    Live leasing data

    Today’s snapshot is replaced by the RentCafe / Yardi API, so availability, rent, plans and office hours refresh on their own and apply links deep-link into the existing flow.

    Wiseman provides API credentials and the account manager · confirmation of canonical property IDs · a fix for the Motor Tides listing URL, which currently reads motor-tabor-by-wiseman.

  4. Phase 3 · ~2 weeks

    Motor Tides

    The flagship gets a dedicated property site on this same system — hero, floor plans, amenities, neighbourhood, tour booking — and proves the property template before it is copied.

    Wiseman provides written rights confirmation for the Vimeo tour library · floor plan files and a signed-off amenity list · leasing phone, hours and tour method · a decision on a standalone domain.

  5. Phase 4 · ~1 week, then rolling

    Motor Midway, then the portfolio

    The proven template is applied to Motor Midway — same street, same architect — then rolled out area by area, heaviest first.

    Wiseman provides per-building photography or a decision to shoot · any building-specific copy worth keeping · on-site manager names and hours.

  6. Phase 5 · ~1 week

    Cutover and handover

    DNS cutover with the full redirect map so no existing link breaks, monitoring and analytics handed over, a written runbook and a working session on updating content.

    Wiseman provides DNS access · final sign-off · who owns the site internally after launch.

The short version

What we need from Wiseman.

Everything else is ours. These are the items that decide whether the schedule holds.

  • Blocks Phase 0

    A founding year, in writing

    LinkedIn says 1980, the contractor licence carries 1982, the Archinect profile says 1985, the Better Business Bureau has 1987. No page states a year until one is chosen.

  • Blocks Phase 0

    A decision on “45 years” and “100+ communities”

    Both are on the current homepage; neither is supported by any public source we could find, and the live feed lists 72 buildings.

  • Blocks Phase 0

    Responsible broker entity and DRE number

    Every principal’s licence reads as expired and no company record exists. The footer needs a correct one before launch.

  • Blocks Phase 0

    Leadership, values and history in the company’s words

    The only name any public source supports is founder Isaac Cohanzad.

  • Phase 2

    RentCafe / Yardi API access

    The single biggest upgrade available: with it, the site maintains itself.

  • Phase 1

    Vector logo files

    The mark has been rebuilt from a 600px PNG; the original vector will be sharper at every size.

  • Phase 3

    Rights confirmation for the video library

    159 embeddable clips are already owned — a real asset — but they carry a third-party watermark.

  • Phase 3

    A photography decision

    The existing library is interiors only. A half-day shoot with a licensed drone operator is the only way to get the actual buildings and streets on screen.

  • Phase 1

    Canonical social handles

    Two Instagram accounts are live and the site data points at the less-followed one.

  • Phase 5

    DNS access and an internal owner

    Needed only at cutover, but worth identifying early.
